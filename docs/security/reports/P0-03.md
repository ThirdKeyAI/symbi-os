# P0-03 preparation evidence

Date: 25 Nov 2026. Parent: `0bf3000` on the P0-02 review branch.

The requested secureblue Hyprland/userns base is retired. The evidence is the
[upstream deprecation notice at 353366bb](https://github.com/secureblue/secureblue/blob/353366bb6d031e66fc565b0b101a8a069f32fcdb/files/system/usr/libexec/deprecated-images.json.md).
No obsolete image was pulled and no substitute compositor was selected.

Tests were written and run before implementation: the first-login copy,
privacy files and renderer tests failed because those files did not exist.
After implementation, twelve offline tests pass. They exercise preservation of
existing settings and links, refusal of unsafe directory/source links, digest
and key-hash validation, and the intended privacy defaults. Seven vendored files
match their retained SHA-256 values. These tests do not verify OCI signatures.

The production configuration deliberately has no base image pin. Rendering it
exits 1 with `base selection is pending; see OQ-07`. Synthetic image digests and
keys exist only inside temporary test fixtures and are never recipe defaults.

The recipe follows BlueBuild v0.9.42's source interface (full revision in
`image/THIRD_PARTY.md`), including its actual `bluebuild: none` setting. The CLI
and generated Containerfile have not been exercised: recipe v2 is a compile-time
feature and the selected runner must qualify the actual pinned executable.

The complete serial workspace check passed in 1.89 seconds with peak RSS
70,348 KiB (about 69 MiB); it is retained in `P0-03-check.log`. The formal
verification drift check also remains in sync. No VM,
container image build or local runtime compilation ran. No hosted CI result,
signature, SBOM, provenance, plugin rejection or Fedora boot result is asserted.
See the card for the precise remaining acceptance gates.

## Signature-policy preparation follow-up

Date: 25 Nov 2026. `image/signing.py` prepares a default-reject containers/image
policy with explicit public-key and signed-repository bindings. It also prepares
signature-attachment settings and prints digest-only signed rebase commands.
Release repositories and ThirdKey public-key custody remain deliberately unset;
the real configuration refuses to create a bundle (`OQ-03`). No system policy
was installed and no signing, publication or rebase was performed.

A regression test first demonstrated that the recipe's public-key path check
accepted an entire `image/keys` directory replaced by a symlink outside that
trusted directory. The renderer and new policy generator now reject that case.
The initial failure is retained in `P0-03-key-path-regression.log`; the final
checks are retained in `P0-03-trust-check.log`.

The complete serial workspace check passed: 22 image tests and six Cedar fixture
tests, formatting, Clippy, Rust tests/docs, cargo-deny and cargo-vet. It took
5.28 seconds with peak RSS 70,572 KiB (about 69 MiB). Formal drift remains in
sync. The policy tests use non-cryptographic key text and do not establish real
signature acceptance or rejection. Image build, Fedora VM, hosted CI, actual
signatures and release qualification remain pending as described above.
