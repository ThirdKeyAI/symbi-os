argv while `/proc/<pid>/exe` remains inaccessible. The controller therefore

uses one shared bounded kernel mountinfo parser in the root mount service, the
unprivileged runner and host report validator. Each guest process opens the
fixed path with `O_PATH|O_DIRECTORY|O_CLOEXEC|O_NOFOLLOW`, obtains its canonical

by device, inode and file type. It does not reopen the path to compare a second
mount ID. A concurrent mount-capable actor could therefore replace a same-inode
mount after the snapshot. That actor is outside this disposable guest's threat
boundary: both services lack mount capability, and each caller independently
rechecks the mounted device and VFS restrictions before use. Revisit this
assumption if a future qualification guest introduces a concurrent mount actor.
