## Offline installed-image qualification runner

The hosted runner now reuses the authenticated P0-03 installation path and adds
a second boot of the unchanged installed disk for P0-04. The workflow checks out
the exact clean upstream revision with recursive submodules, rejects Git
credential/routing configuration, and builds a private ext4 source disk with a
recorded tree, Cargo lock, submodule inventory, UUID and full-disk hash. QEMU
attaches that disk read-only with `nosuid,nodev,noexec`; no host filesystem share,
NIC, login, SSH credential or release key exists.

Systemd's `fstab.extra` boot credential creates the correctly named mount. A
fixed root setup service creates only disposable UID 10001 and its delegated user
manager in the guest overlay. The ordinary runner has no capabilities or new
privileges. It executes the pinned driver against the image's exact installed
binary, while the separate fixed status service supplies two bounded deployment
reports. Systemd itself powers off on runner success or failure, so the test user
does not receive shutdown authority.

Only the driver's explicit public-report allowlist can cross the virtio-serial
channel. Each regular file is hash-bound, capped at 2 MiB, compressed and checked
again by the controller; total expanded evidence is capped at 12 MiB. Paths to
private action fixtures and key-like files are rejected, every retained path
component is opened without following symlinks, and raw outer-wrapper console
output is represented only by byte counts and hashes. The source disk and
24 GiB installed disk are rehashed after the run, and the parent, QEMU and guest
services retain CPU, memory, PID and zero-host-swap ceilings.
