## Acceptance

- Each model exhaustively checks its finite config with all faults disabled.
- All ordinary transitions execute; the fault-only declassification action is
  explicitly excluded from normal action-coverage expectations.
- Every row in [the fault matrix](../../formal/faults.tsv) breaks its named
  security rule, including revoke/freeze races and crash-before-sync.
- Drift checks cover the specification, models, configs and checker setup.
- GitHub and Gitea CI run the commit-pinned formal-proofs action after the existing workspace
  check, using one visible CPU and a 256 MiB heap.
- A cold reader follows the record on a seeded model regression and harmless
  refactor; evidence and limits are retained in the card report.

New journal events: none. Real event schemas and trace instrumentation must
be added with the implementation; synthetic model traces are not runtime logs.
New Cargo dependencies: none. Checker dependencies are documented in
[dependency notes](../dependencies.md).

## Threat note

An incomplete model or stale mapping can provide false assurance for a broken
authority boundary. Explicit bounds, per-rule fault checks, action coverage,
drift detection and independent record review reduce that risk. They do not
replace TCB implementation review or real trace/VM/escape qualification.
