## Fixed non-root bootc-status bridge

The qualification driver no longer invokes privileged bootc status directly.
It requires the root-owned `/run/symbi-qualification/status.sock` and reads one
report before and one after the upstream suites. The new `q.service` can execute
only `/usr/bin/bootc status --json`; its server accepts exactly two non-root

only `CAP_SYS_ADMIN`, 256 MiB memory, half a CPU, 32 tasks and zero swap. The
driver receives boot metadata only and gains no command, sudo or policy-changing

`containerPolicy` reference.

## Offline installed-image qualification runner

The hosted runner now reuses the authenticated P0-03 installation path and adds
a second boot of the unchanged installed disk for P0-04. The workflow checks out
the exact clean upstream revision with recursive submodules, rejects Git
credential/routing configuration, and builds a private ext4 source disk with a
recorded tree, Cargo lock, submodule inventory, UUID and full-disk hash. QEMU
attaches that disk read-only with `nosuid,nodev,noexec`; no host filesystem share,
NIC, login, SSH credential or release key exists.

A fixed systemd mount binds the source's stable virtio identity in the main
namespace. A capability-free root service verifies its exact filesystem metadata
before a separate setup service creates only disposable UID 10001 and its delegated
user manager in the guest overlay. The ordinary runner has no capabilities or
new privileges. It executes the pinned driver against the image's exact
installed binary, while the fixed status service supplies two bounded deployment
reports. Systemd itself powers off on runner success or failure, so the test user
does not receive shutdown authority.

Only the driver's explicit public-report allowlist can cross the virtio-serial
channel. Each regular file is hash-bound, capped at 2 MiB, compressed and checked
again by the controller; total expanded evidence is capped at 12 MiB. Paths to
private action fixtures and key-like files are rejected, every retained path
component is opened without following symlinks, and raw outer-wrapper console
output is represented only by byte counts and hashes. The source disk and
24 GiB installed disk are rehashed after the run, and the parent, QEMU and guest
services retain CPU, memory, PID and zero-host-swap ceilings.

The missing-module test failed first. All eight new hosted-runner tests, 297
image tests, 20 qualification tests and six Cedar policy tests now pass. The
initial complete serial repository gate finished in 3.44 seconds with 69,504

## First native boot failure and bounded correction

[Hosted run 45938162268](https://github.com/ThirdKeyAI/symbi-os/actions/runs/45938162268)
passed authenticated installation and the ordinary Atomic boot. Its second boot
never reached a Landlock service: QEMU exposed the installed raw disk as a
guest-read-only snapshot, so OSTree could not remount `/etc` writable and the
guest entered emergency mode. The 95-minute controller timeout was then masked
by a `PermissionError` while signaling QEMU. The retained parent cleanup still
removed all four containers, loop devices, image, storage and runroot, with zero
OOM, OOM-kill or swap events. No native qualification was produced.

The corrected controller creates an explicit writable qcow2 overlay backed by
the read-only installed raw image and discards the overlay before bounded public
evidence retention. The source disk remains guest-read-only, but now uses the
fixed `SYMBIQUAL` virtio serial. A dedicated 128 MiB, zero-swap
service waits at most 30 seconds for `/dev/disk/by-id/virtio-SYMBIQUAL`, verifies
the exact ext4 type, label and generated UUID after systemd mounts that fixed
device in the main namespace at `/run/symbi-qualification/source` with
`ro,nosuid,nodev,noexec`. The prior label-only `fstab.extra` source is replaced
by the fixed by-id path and a 30-second device timeout. The unprivileged driver
binds its report to the root-owned device record, and controller cleanup records
signal errors without replacing the primary failure or suppressing final cgroup
data.

The compact [failed-run record](../security/reports/P0-04-landlock/45938162268/summary.json)
binds the run, artifact, installed disk, source disk, retained evidence hashes,
resource counters and correction without adding raw logs. Five focused contract
tests and all 19 hosted Landlock tests pass; the latter completed in 0.198 seconds
at 31,896 KiB peak RSS and zero swap. The complete serial image suite passes all
382 tests in 2.339 seconds at 58,224 KiB peak RSS and zero swap, and systemd
accepts all four staged units. A fresh exact-head hosted run remains mandatory
before any Landlock, containment or OS qualification claim.

A later hosted Atomic probe showed that whitespace parsing of formatted
`findmnt` output can reject an otherwise valid source mount. P0-04 used the same
display-oriented pattern in both its root mount service and unprivileged runner,
so the rerun was held before publication. A shared bounded parser now reads the
kernel mountinfo record directly, decodes only the four specified octal escapes,
and opens the fixed path with `O_PATH|O_DIRECTORY|O_CLOEXEC|O_NOFOLLOW`. A
bounded `/proc/self/fdinfo/<fd>` read identifies the exact row currently visible
through that descriptor even when the same path has stacked mount rows. No
row-order or highest-ID heuristic is accepted. The selected row binds `/`, ext4,
the direct virtio source, its major/minor number and
`ro,nosuid,nodev,noexec`. The root service also binds
the mounted filesystem device number to the direct block node. The guest records
the compact observation, total path matches and visible and selected mount IDs
before validation, and the host revalidates it before accepting a report.
Duplicate selected IDs, a missing selected ID, path replacement, symlinks,
changed roots/devices/filesystems, missing flags, `rw`, malformed or oversized
fdinfo or mountinfo, invalid escapes and NULs fail closed.

The fail-first test could not import the absent shared parser. After the fix,
all 27 focused hosted Landlock tests pass in 0.199 seconds at 32,384 KiB peak
RSS and zero swaps; all six shared container-input tests pass in 0.005 seconds
at 27,196 KiB peak RSS and zero swaps.
AST parsing, patch whitespace and verification of the four staged systemd units
also pass. This is inert preflight evidence; the exact-head native run is still
required.
