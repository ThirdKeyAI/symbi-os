The [guest driver](../../image/qualification/landlock.py) checks a clean pinned
runtime source, authenticated binary digest supplied by the builder, matching
bootc deployment, enforcing SELinux and a bounded non-root Fedora guest. It runs
the exact upstream platform/full-release drivers and rejects shortened, failed,
wrong-binary or refusal-only results. Nine offline tests cover report validation
and publication filtering. They use synthetic fixtures and do not qualify a runtime.

The [procedure](../../image/qualification/README.md) describes resource limits,
retained public evidence and private signing-key exclusions. The actual Fedora
report, full escape/VM results and upstream control-catalog registration remain
pending the built P0-03 image, OQ-06 control registration and OQ-08's completed
runtime validation. Neither the Ubuntu host nor an older public
3.0.0 binary is accepted as the requested platform.

Four bounded local build attempts produced no binary: the
[first](../security/reports/P0-04-runtime-build-attempt.json) and one retry timed
out; two [follow-ups](../security/reports/P0-04-runtime-build-followups.json) hit
their cgroup memory ceiling. The exact source pin and 1 GiB hard host RAM limit
remain unchanged. A disposable Ubuntu VM with guest-disk swap subsequently
completed `cargo build --workspace --locked` in 105m16s, then failed two
runtime tests (1,520 passed, 13 ignored). Both failures reproduced once with
the cached binary. The scheduler fixture requires more concurrent reservation
capacity than this deliberately small VM provides; the coordinator failure's
cause is not yet established. Clippy/format evidence remains pending from the
separate diagnostic unit. The [terminal record](../security/reports/P0-04-runtime-terminal/baseline/result.json)
preserves the clean source and unchanged resource caps. No full-pass marker,
Fedora qualification or containment result is claimed.
