## PR 24 between-case checkpoint review

The supplied review's P2 finding is confirmed: the filesystem driver created its
container configuration once and did not call artifact verification in its
per-case `Backend.cleaned()` checkpoint. A changed executable or sidecar could
therefore pass that checkpoint and be restored before final verification. The
existing sixteen helper tests did not exercise this missing caller.

The revised fixture patch adds that checkpoint and a test using the real
`Backend` with a synthetic Docker interface. Six mutations (runsc bytes, sidecar
bytes, permissions, addition, removal and registered-path change) failed to be
rejected before the fix. After the fix all seventeen tests pass, including
unchanged intermediate and restored completion controls. The first fix test run
rejected all six changes but one assertion expected a different error message
for an empty sidecar directory; its message expectation was corrected and the
suite passed. Raw red, first-fix and final-pass logs are retained under
`P0-05-pr24-checkpoint/` with exact file hashes. The final check used 24,604 KiB
peak RSS and 0.05 CPU seconds under the local 128 MiB/10% CPU cap.

The new six-file cumulative patch hash is
`a4545649b1c83f0a3402781f815ebc66ea2b507128d17f61e76c4febb5017bda`.
No runtime code, Cargo dependency, OS runtime pin or sandbox policy changes.
Full hosted workspace checks of this patch are pending before the upstream
follow-up commit, as required by upstream AGENTS.md. PR 24 stays a draft and
unmerged. Its Windows job failed and its main job is still running; those are
separate from the reproduced fixture issue. Live qualification must be rerun
against the revised patch after it is published.
